## Overview

Three animated SVGs are generated and embedded in `README.md`:

| SVG | Description | Animation |
|-----|-------------|-----------|
| `generated/avi-ascii.svg` | ASCII portrait | Characters type in, blinking cursor |
| `generated/info-card.svg` | Neofetch-style terminal card | Rows slide + fade in |
| `generated/contrib-heatmap.svg` | 53-week contribution calendar | Diagonal reveal wave |

All animations play **once** on page load, then freeze.  The cursor blinks indefinitely.

**Why no JavaScript?**  GitHub strips `<script>` tags from README SVGs.  All animations use **SMIL** (Synchronized Multimedia Integration Language) — the native SVG animation standard — which GitHub renders natively via the browser SVG engine.

## Quick Start

### 1. Clone / fork this repository into your `<username>/<username>` GitHub profile repo

```bash
git clone https://github.com/fortune-c/fortune-c.git
cd fortune-c
```

### 2. Replace the portrait

Copy your photo to `assets/profile.png` (JPEG or PNG, any resolution).

### 3. Edit `config.yaml`

Change at minimum:
- `github_username`
- `display_name`
- `title`
- `info_rows` (your OS, editor, stack, etc.)
- `links`

### 4. Create and activate a virtual environment

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r scripts/requirements.txt
```

> **Note:** `rembg` downloads a ~170 MB neural network model (U²-Net) on first use.
> This only happens once; subsequent runs use the cached model.

### 5. Run the pipeline

```bash
# Step 1: Remove background, convert to greyscale, apply CLAHE, resize
python scripts/prep_photo.py

# Step 2: Generate animated ASCII SVG
python scripts/make_ascii_svg.py

# Step 3: Generate animated info card SVG
python scripts/make_info_card.py

# Step 4: Fetch contribution data from GitHub (no token required)
python scripts/fetch_contributions.py

# Step 5: Render contribution heatmap SVG
python scripts/render_heatmap_svg.py
```

### 6. Preview locally

Open `README.md` in a Markdown viewer that renders SVG.  
Or open the individual SVGs in a browser: `file:///path/to/generated/contrib-heatmap.svg`

### 7. Commit and push

```bash
git add .
git commit -m "feat: animated profile README"
git push
```

GitHub will render the SVGs in your profile README automatically.

## Customisation

### Changing the colour theme

All colours live under `theme:` in `config.yaml`.  The Catppuccin Mocha defaults are chosen for elegance; swap any hex value to restyle.

Heatmap cell colours are separately controlled under `heatmap_colors:` (list of 5 hex values, index 0 = no contributions).

### Adjusting the portrait ASCII width

```yaml
portrait:
  ascii_width_chars: 72     # wider = more detail, bigger SVG
  char_height_ratio: 0.55   # <1 = compress vertically (fix aspect ratio)
  brightness_ramp: " .`:-=+*cs#%@"
```

Increase `ascii_width_chars` for more detail; lower `svg_font_size_px` to fit.

### Changing animation speed

```yaml
animation:
  ascii_char_delay_ms: 12        # ms per character – lower = faster typing
  card_row_stagger_ms: 120       # ms between info card rows appearing
  card_row_duration_ms: 400      # ms for each row's fade+slide

heatmap:
  stagger_ms: 6                  # ms per diagonal step
  reveal_duration_ms: 300        # ms for each cell's fade-in
```

### Adding / removing info card rows

Edit the `info_rows:` list in `config.yaml`.  Each entry is a `{label, value}` pair.  The card height auto-adjusts.

```yaml
info_rows:
  - label: "OS"
    value: "Arch Linux"
  - label: "Editor"
    value: "Neovim"
  # Add as many rows as you like
```

## Script Reference

### `scripts/shared.py`

Core utility library imported by all generators.  Never run directly.

**Key exports:**

| Name | Type | Purpose |
|------|------|---------|
| `load_config()` | function | Load `config.yaml` |
| `Palette` | dataclass | Typed colour palette |
| `svg_root()` | function | Create `<svg>` element |
| `rect()`, `text_el()`, `line_el()` | functions | SVG element builders |
| `animate()`, `animate_transform()`, `set_attr()` | functions | SMIL animation builders |
| `cursor_blink_rect()` | function | Blinking cursor element |
| `draw_terminal_chrome()` | function | macOS-style window chrome |
| `glow_filter()` | function | Soft glow `<filter>` element |
| `write_svg()` | function | Serialise SVG to disk |
| `ms_to_smil()` | function | `1234` → `"1.234s"` |

### `scripts/prep_photo.py`

**Input:** `assets/profile.png`  
**Output:** `assets/profile_clean.png`

Pipeline: background removal (rembg U²-Net) → greyscale → CLAHE → white composite → resize.

```bash
python scripts/prep_photo.py [--config path/to/config.yaml]
```

### `scripts/make_ascii_svg.py`

**Input:** `assets/profile_clean.png`  
**Output:** `generated/avi-ascii.svg`

Converts the cleaned image to an ASCII grid, then generates an SVG where each character is individually animated via SMIL `<set>` elements.

```bash
python scripts/make_ascii_svg.py [--config path/to/config.yaml]
```

---

### `scripts/make_info_card.py`

**Input:** `config.yaml`  
**Output:** `generated/info-card.svg`

Builds a terminal window chrome with animated rows that slide and fade in.

```bash
python scripts/make_info_card.py [--config path/to/config.yaml]
```

## GitHub Actions

The workflow at `.github/workflows/update-profile-art.yml` runs:

1. **Daily at 04:00 UTC** (configurable)
2. **On manual dispatch** from the Actions tab

Steps:
1. Checkout repository
2. Setup Python 3.11
3. Install dependencies (cached)
4. Fetch contributions
5. Render heatmap
6. Render ASCII portrait
7. Render info card
8. Auto-commit with `[skip ci]` to prevent re-triggering

The commit only happens if files actually changed (via `git diff --cached --quiet`).

### Enabling the workflow

1. Push this repository to your `<username>/<username>` profile repo.
2. Go to **Settings → Actions → General → Allow all actions**.
3. The workflow will run automatically on schedule.
4. To trigger manually: **Actions → Update Profile Art → Run workflow**.

### Skipping photo pre-processing

The portrait pre-processing step (rembg, CLAHE) only needs to run when you update `assets/profile.png`.  The default manual dispatch skips it to keep the daily run fast.  Set `skip_photo_prep = false` to force re-processing.

## Troubleshooting

### `[prep_photo] Missing dependency: rembg`

```bash
pip install rembg
```

The first run downloads ~170 MB of model weights to `~/.u2net/`.

---

### `[make_ascii_svg] Cleaned image not found`

Run `prep_photo.py` before `make_ascii_svg.py`.

---

### `[fetch_contributions] No contribution cells found`

GitHub may have changed their HTML structure.  Check:

```bash
curl -s "https://github.com/users/fortune-c/contributions" | grep "data-date" | head -5
```

If the attribute names changed, update `parse_contributions()` in `fetch_contributions.py` accordingly.

---

### SVG animations don't play on GitHub

- Animations use SMIL, which requires the SVG to be embedded via `<img src="...">` — not inline `<svg>`.  The README already does this correctly.
- GitHub's CDN caches SVGs aggressively.  After pushing a new version, append `?v=2` to the `src` URL temporarily to bust the cache, then remove it.
- Some browser extensions (e.g. aggressive CSP or ad blockers) can block SMIL.  Test in a clean browser profile.

---

### The heatmap shows all empty cells

Run `fetch_contributions.py` first.  Check `data/contributions.json` exists and has `days` with actual entries.

---

### Portrait looks stretched / squashed

Adjust `char_height_ratio` in `config.yaml`:
- If the portrait looks too tall: increase the ratio (e.g. `0.55` → `0.65`)
- If the portrait looks too wide: decrease the ratio (e.g. `0.55` → `0.45`)

---

### SVGs are huge / slow to load

Reduce `ascii_width_chars` (e.g. from `72` to `48`) or increase `svg_font_size_px` so there are fewer total characters to animate.
